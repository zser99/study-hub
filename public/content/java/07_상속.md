# 7강. 상속

## 학습 목표
클래스 간에 코드를 재사용하는 상속의 개념, 메서드 오버라이딩, `super` 키워드, 상속과 생성자·접근 제어의 관계를 이해한다.

## 1. 상속이 필요한 이유
에어컨(AirConditioner)과 히터(Heater)를 만든다고 하자.
```java
public class AirConditioner {
    public void powerOn() {
        System.out.println("전원을 켭니다.");
    }
    public void coolAir() {
        System.out.println("찬 바람이 나옵니다.");
    }
}

public class Heater {
    public void powerOn() {
        System.out.println("전원을 켭니다.");
    }
    public void warmAir() {
        System.out.println("따뜻한 바람이 나옵니다.");
    }
}
```
둘 다 `powerOn()`의 내용이 완전히 똑같다. 에어컨과 히터는 결국 "가전제품(Appliance)"이라는 더 추상적인 개념의 구체적인 예시이고, 전원을 켜는 동작은 공통이다. 이렇게 여러 클래스에 공통되는 부분이 있을 때 **상속(inheritance)**을 사용하면 중복을 없앨 수 있다.

## 2. 상속 관계 만들기
`extends` 키워드로 상속을 표현한다.
```java
public class Appliance {
    public void powerOn() {
        System.out.println("전원을 켭니다.");
    }
}

public class AirConditioner extends Appliance {
    public void coolAir() {
        System.out.println("찬 바람이 나옵니다.");
    }
}

public class Heater extends Appliance {
    public void warmAir() {
        System.out.println("따뜻한 바람이 나옵니다.");
    }
}
```
```java
AirConditioner ac = new AirConditioner();
ac.powerOn();   // 상속받은 기능
ac.coolAir();
```
- **부모 클래스(슈퍼클래스)**: `Appliance`처럼 필드와 메서드를 물려주는 클래스.
- **자식 클래스(서브클래스)**: `AirConditioner`, `Heater`처럼 물려받는 클래스.
- 자식은 부모의 기능을 물려받아 쓸 수 있지만, 그 반대(부모가 자식의 기능을 아는 것)는 성립하지 않는다.

**자바는 다중 상속을 지원하지 않는다.** `extends` 뒤에는 클래스를 하나만 지정할 수 있다. 여러 부모를 동시에 상속받으면, 두 부모에 같은 이름의 메서드가 있을 때 어느 쪽을 써야 할지 애매해지는 "다이아몬드 문제"가 생기기 때문이다. (부모가 또 다른 부모를 갖는 여러 단계의 상속은 가능하다.)

## 3. 상속과 메모리 구조
`new AirConditioner()`를 호출하면, 메모리에는 `AirConditioner`뿐 아니라 부모인 `Appliance`의 내용까지 함께 생성된다. 겉으로는 인스턴스 하나지만, 내부에는 부모와 자식의 정보가 함께 존재하는 것이다.

메서드를 호출할 때는 **호출에 사용한 변수의 타입**을 기준으로 먼저 찾고, 없으면 부모 타입으로 올라가며 찾는다.
```java
AirConditioner ac = new AirConditioner();
ac.coolAir();   // AirConditioner 타입에 있음 -> 바로 실행
ac.powerOn();   // AirConditioner에는 없음 -> 부모 Appliance에서 찾아 실행
```
부모를 계속 거슬러 올라가도 못 찾으면 컴파일 오류가 발생한다.

## 4. 상속과 기능 추가
공통 기능을 추가하고 싶다면 부모 클래스 하나만 고치면 된다.
```java
public class Appliance {
    public void powerOn() { ... }
    public void powerOff() {   // 새로 추가
        System.out.println("전원을 끕니다.");
    }
}
```
이렇게 하면 `AirConditioner`, `Heater`뿐 아니라 앞으로 추가될 모든 자식 클래스가 자동으로 `powerOff()`를 쓸 수 있다. 상속 관계가 아니었다면 각 클래스마다 일일이 추가해야 했을 것이다.

## 5. 메서드 오버라이딩
자식이 부모의 기능을 그대로 쓰지 않고 다르게 재정의하고 싶을 수 있다. 예를 들어 에어컨은 켤 때 "냉방을 시작합니다"라고 더 구체적으로 알리고 싶다.
```java
public class AirConditioner extends Appliance {
    @Override
    public void powerOn() {
        System.out.println("냉방을 시작합니다.");
    }
    public void coolAir() { ... }
}
```
이렇게 부모의 메서드를 자식에서 같은 이름으로 다시 정의하는 것을 **메서드 오버라이딩(Overriding)**이라 한다. 이제 `ac.powerOn()`을 호출하면 `Appliance.powerOn()`이 아니라 `AirConditioner.powerOn()`이 실행된다.

`@Override`는 애노테이션으로, "이 메서드는 부모 메서드를 오버라이딩한 것"임을 컴파일러에게 알려준다. 필수는 아니지만 붙여두면, 오버라이딩 조건을 잘못 지켰을 때(예: 부모에 그런 메서드가 없는 경우) 컴파일러가 바로 오류를 잡아준다.

**오버라이딩 성립 조건**: 메서드 이름, 매개변수(타입·순서·개수)가 부모와 완전히 같아야 하고, 반환 타입도 같아야 한다(또는 하위 타입). 접근 제어자는 부모보다 더 좁아질 수 없다(부모가 `protected`면 자식은 `protected`나 `public`만 가능). `static`, `final`, `private`이 붙은 메서드는 오버라이딩할 수 없고, 생성자도 오버라이딩 대상이 아니다.

**오버로딩(Overloading)과 헷갈리지 말자**: 오버로딩은 같은 클래스 안에서 이름은 같고 매개변수 구성이 다른 메서드를 여러 개 만드는 것(4강 참고)이고, 오버라이딩은 상속 관계에서 부모의 메서드를 자식이 재정의하는 것이다.

## 6. 상속과 접근 제어
자식 클래스는 부모의 `public`, `protected` 필드/메서드에는 접근할 수 있지만, `default`(package-private), `private`에는 접근할 수 없다. 특히 자식과 부모가 서로 다른 패키지에 있는 경우 이 차이가 중요하다.
```java
// package appliance;
public class Appliance {
    public int publicValue;
    protected int protectedValue;
    int defaultValue;       // package-private
    private int privateValue;
}
```
```java
// package appliance.custom;
public class SmartHeater extends Appliance {
    void check() {
        publicValue = 1;      // OK: public
        protectedValue = 1;   // OK: 패키지가 달라도 상속 관계라 접근 가능
        // defaultValue = 1;  // 오류: 다른 패키지의 default는 접근 불가
        // privateValue = 1;  // 오류: private은 어디서도 직접 접근 불가
    }
}
```

## 7. super - 부모 참조
자식과 부모의 필드 이름이 같거나, 메서드를 오버라이딩해서 부모의 원래 버전을 쓸 수 없게 됐을 때, `super`를 쓰면 부모 쪽을 명시적으로 가리킬 수 있다.
```java
public class Appliance {
    String status = "대기중";
    void report() {
        System.out.println("Appliance.report");
    }
}

public class AirConditioner extends Appliance {
    String status = "냉방중";   // 부모와 이름이 같은 필드

    @Override
    void report() {
        System.out.println("AirConditioner.report");
    }

    void checkStatus() {
        System.out.println("this.status = " + this.status);     // 냉방중
        System.out.println("super.status = " + super.status);   // 대기중
        this.report();    // AirConditioner.report
        super.report();   // Appliance.report
    }
}
```
`this`가 자기 자신(현재 타입)을 가리키듯, `super`는 부모 타입을 가리킨다. 이름이 겹치는 상황에서 `super`를 쓰면 명확히 부모의 것을 지목할 수 있다.

## 8. super - 생성자 호출
상속 관계의 인스턴스를 생성하면 부모 부분도 함께 만들어지므로, **부모의 생성자도 반드시 호출되어야 한다.** 그래서 자식 생성자의 **첫 줄에는 반드시 `super(...)`로 부모 생성자를 호출**해야 한다.
```java
public class Appliance {
    public Appliance() {
        System.out.println("Appliance 생성자");
    }
}

public class AirConditioner extends Appliance {
    public AirConditioner() {
        super();   // 부모 생성자 호출 (기본 생성자면 생략 가능)
        System.out.println("AirConditioner 생성자");
    }
}
```
```java
new AirConditioner();
```
```
Appliance 생성자
AirConditioner 생성자
```
**규칙**: 자식 생성자 첫 줄에 `super(...)`를 직접 쓰지 않으면, 자바가 자동으로 부모의 **기본 생성자**를 호출하는 `super()`를 넣어준다. 그런데 부모에 매개변수 있는 생성자만 있고 기본 생성자가 없다면, 이 자동 삽입이 불가능해 컴파일 오류가 난다 — 이 경우 명시적으로 `super(인수...)`를 호출해야 한다.

**this(...)와 함께 쓸 때**: 생성자 첫 줄에 `this(...)`(같은 클래스의 다른 생성자 호출, 4강 참고)를 쓸 수도 있지만, 결국 그 체인의 어딘가에서는 `super(...)`가 반드시 한 번 호출되어야 한다.

**생성 순서**: 상속 관계의 생성자는 항상 **최상위 부모부터 자식 순서로 실행**된다. 자식 생성자 첫 줄이 부모 생성자를 먼저 호출하기 때문에, 결과적으로 부모의 초기화가 끝나야 자식 초기화가 이어진다.

## 9. final과 상속
- **`final` 클래스**: 상속 자체를 금지한다. `public final class Appliance { ... }`처럼 선언하면 다른 클래스가 이를 상속할 수 없다.
- **`final` 메서드**: 오버라이딩을 금지한다. 자식 클래스에서 그 메서드를 재정의할 수 없다.

## 핵심 정리
| 개념 | 설명 |
|---|---|
| extends | 상속 관계를 표현, 부모는 하나만 지정 가능 |
| 메서드 오버라이딩 | 자식이 부모의 메서드를 같은 시그니처로 재정의 |
| @Override | 오버라이딩임을 명시, 조건 오류를 컴파일 시점에 검증 |
| super | 부모 타입의 필드/메서드/생성자를 명시적으로 참조 |
| 생성자 호출 순서 | 부모 -> 자식 순서로 실행 |
| final 클래스/메서드 | 각각 상속 금지 / 오버라이딩 금지 |
