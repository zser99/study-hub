# 1강. 클래스와 데이터

## 학습 목표
클래스와 객체가 왜 필요한지, 배열만으로 데이터를 관리할 때의 한계를 통해 이해한다.

## 1. 문제: 여러 게임 캐릭터 정보 관리하기
게임 캐릭터는 이름, 레벨, 체력을 가진다. 이를 코드로 표현하는 방법을 단계적으로 발전시켜보자.

### 1) 변수를 각각 선언 (가장 단순한 방법)
```java
String player1Name = "전사";
int player1Level = 5;
int player1Hp = 100;

String player2Name = "마법사";
int player2Level = 3;
int player2Hp = 60;

System.out.println(player1Name + " Lv." + player1Level + " HP:" + player1Hp);
System.out.println(player2Name + " Lv." + player2Level + " HP:" + player2Hp);
```
캐릭터가 2명일 때는 그럭저럭 괜찮지만, 캐릭터가 10명, 100명이 되면 변수를 그만큼 계속 추가해야 한다. 코드 양이 캐릭터 수에 비례해서 계속 늘어나는 게 근본 문제다.

### 2) 배열 사용
```java
String[] names = {"전사", "마법사"};
int[] levels = {5, 3};
int[] hps = {100, 60};

for (int i = 0; i < names.length; i++) {
    System.out.println(names[i] + " Lv." + levels[i] + " HP:" + hps[i]);
}
```
캐릭터 추가는 편해졌다(배열에 원소만 추가하면 됨). 하지만 새로운 문제가 생긴다.

**배열 사용의 한계**
- 캐릭터 한 명의 데이터가 `names`, `levels`, `hps`라는 서로 다른 3개 배열에 흩어져 있다.
- 특정 캐릭터를 제거하거나 정렬하려면, 3개 배열 모두에서 **같은 인덱스**를 정확히 찾아 함께 처리해야 한다. 하나라도 인덱스가 어긋나면 이름은 "전사"인데 레벨은 마법사의 레벨이 붙는 식의 버그가 생긴다.
- 컴퓨터 입장에서는 아무 문제 없이 동작하지만, **사람이 코드를 관리하기에는 실수하기 쉬운 구조**다.

즉, 근본 원인은 "이름/레벨/체력이 원래 한 캐릭터에 속한 데이터인데, 코드에서는 서로 다른 자료구조에 뿔뿔이 나뉘어 있다"는 점이다.

## 2. 클래스 도입
이름, 레벨, 체력을 "캐릭터"라는 하나의 개념으로 묶는다.

```java
public class Player {
    String name;
    int level;
    int hp;
}
```
- `class` 키워드로 캐릭터 클래스(`Player`)를 정의한다.
- 클래스 안에 선언한 변수를 **멤버 변수(Member Variable)** 또는 **필드(Field)**라 부른다. 특정 클래스에 소속된 변수라는 뜻이다.
- 클래스명은 관례상 대문자로 시작하고 낙타 표기법을 쓴다 (예: `Player`, `GameItem`, `BattleManager`). 반면 기본형 타입(`int`, `boolean` 등)은 소문자로 시작한다 — 이 규칙만 봐도 "이건 클래스구나"를 구분할 수 있다.

```java
Player player1 = new Player();
player1.name = "전사";
player1.level = 5;
player1.hp = 100;

Player player2 = new Player();
player2.name = "마법사";
player2.level = 3;
player2.hp = 60;

System.out.println(player1.name + " Lv." + player1.level + " HP:" + player1.hp);
System.out.println(player2.name + " Lv." + player2.level + " HP:" + player2.hp);
```
실행 결과:
```
전사 Lv.5 HP:100
마법사 Lv.3 HP:60
```
캐릭터가 늘어나도 캐릭터 한 명의 데이터가 **하나의 객체 안에** 모여있으므로, 어떤 캐릭터를 지우거나 옮길 때 그 캐릭터에 해당하는 객체 하나만 다루면 된다. 배열처럼 여러 자료구조의 인덱스를 맞출 필요가 없다.

## 3. 클래스, 객체, 인스턴스
- **클래스(Class)**: 사용자 정의 타입을 만들기 위한 설계도. `int`, `String`처럼 언어가 기본 제공하는 타입 외에, 개발자가 직접 정의하는 타입이라고 보면 된다.
- **객체(Object) / 인스턴스(Instance)**: 클래스(설계도)를 기반으로 실제 메모리에 만들어진 실체. 이 둘은 사실상 같은 의미로 혼용된다. "Player 클래스를 기반으로 인스턴스를 생성했다"와 "Player 객체를 생성했다"는 같은 말이다.

### `new Player()`가 일어나는 과정
1. `new 클래스명()` 으로 메모리(정확히는 힙 영역)에 실제 `Player` 객체(인스턴스)를 생성한다. 이때 클래스에 정의된 필드 개수만큼 저장 공간이 함께 만들어진다.
2. 생성된 객체는 메모리 어딘가의 참조값(주소, 예: `a001`)을 반환한다. 이 참조값이 없으면 방금 만든 객체를 다시 찾아갈 방법이 없다.
3. `Player player1 = new Player();` 코드는 사실상 아래 두 단계를 합친 것이다.
```
Player player1;              // ① 변수 선언 (아직 아무 것도 가리키지 않음)
player1 = new Player();      // ② 객체 생성 후 반환된 참조값(a001)을 player1에 저장
```
이후 `player1.name = "전사"`처럼 `.`(dot)을 사용하면, `player1`에 저장된 참조값을 따라가 실제 메모리에 있는 객체의 필드에 접근해서 값을 넣는다.

### 인스턴스는 서로 독립적이다
`player1`, `player2`는 각각 `new Player()`로 따로 생성했기 때문에 서로 다른 참조값(예: `a001`, `a002`)을 가진다. 그래서 `player1.hp`를 바꿔도 `player2.hp`에는 아무 영향이 없다. (참고: 만약 `player2 = player1`처럼 **참조값 자체를 복사**하면 둘이 같은 객체를 가리키게 되는데, 이 원리는 2강에서 자세히 다룬다.)

## 4. 배열 + 클래스: 두 방식의 장점을 합치기
클래스로 캐릭터 하나를 깔끔하게 표현했다면, 여러 캐릭터는 다시 배열로 묶으면 된다. 이번에는 배열 하나에 `Player` 객체들을 담으므로, 1번에서 겪었던 "3개 배열의 인덱스를 맞추는" 문제가 사라진다.
```java
Player[] players = new Player[2];
players[0] = player1;
players[1] = player2;

for (Player p : players) {
    System.out.println(p.name + " Lv." + p.level + " HP:" + p.hp);
}
```
캐릭터를 하나 제거하고 싶으면 `players` 배열에서 그 캐릭터가 담긴 자리 하나만 처리하면 된다. 더 이상 여러 배열을 동시에 신경 쓸 필요가 없다.

## 핵심 정리
| 개념 | 설명 |
|---|---|
| 클래스 | 사용자 정의 타입의 설계도 |
| 객체/인스턴스 | 클래스를 기반으로 메모리에 생성된 실체 |
| 멤버 변수(필드) | 클래스에 소속된 변수 |
| 참조값 | 객체가 저장된 메모리 위치, 변수에 담아 객체에 접근 |

**왜 클래스가 필요한가**: 서로 관련된 데이터(이름, 레벨, 체력)를 하나의 단위로 묶어, 사람이 이해하고 관리하기 쉬운 코드를 만들기 위함이다. 배열만으로는 관련 데이터가 흩어져 관리 실수가 발생하기 쉽다.
