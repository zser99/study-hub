# 2강. 기본형과 참조형

## 학습 목표
변수의 두 가지 타입(기본형/참조형)이 대입과 메서드 호출에서 어떻게 다르게 동작하는지 이해한다.

## 1. 기본형 vs 참조형
자바의 데이터 타입은 크게 둘로 나뉜다.

- **기본형(Primitive Type)**: `int`, `long`, `double`, `boolean` 등. 변수 안에 실제 값 자체가 들어있다.
- **참조형(Reference Type)**: 클래스로 만든 타입(직접 정의한 객체, 배열 등). 변수 안에는 실제 값이 아니라 그 값이 저장된 메모리 위치(참조값)만 들어있다.

```java
int score = 10;          // 기본형: score 안에 실제 값 10이 들어있음
Box box = new Box();     // 참조형: box 안에는 Box 객체가 있는 위치(주소)만 들어있음
```

**연산 가능 여부가 핵심 차이다.**
- 기본형은 변수 안에 실제 값이 있으므로 `+`, `-` 같은 연산을 바로 할 수 있다.
- 참조형은 변수 안에 위치 정보(주소)만 있으므로 그 자체로는 연산이 불가능하다. `box1 + box2`처럼 객체끼리 더하는 것은 컴파일 오류다. 다만 `.`으로 객체 내부의 기본형 필드에 접근하면(`box1.value + box2.value`) 그 필드끼리는 연산할 수 있다.

**구분 팁**: 소문자로 시작하면 기본형(`int`, `boolean`...), 대문자로 시작하면 참조형(직접 만든 클래스는 모두 참조형). 단, `String`은 예외적으로 클래스(참조형)이지만, 문자열 값을 `String s = "hi";`처럼 기본형과 똑같이 편하게 다룰 수 있도록 자바가 특별히 지원한다.

## 2. 변수 대입의 대원칙: 항상 "값을 복사"해서 대입한다
자바에서 `A = B`는 B의 실체를 A로 옮기는 게 아니라, **B 변수 안에 든 값을 복사해서 A에 넣는 것**이다. 이 원칙은 기본형이든 참조형이든 동일하다. 다만 그 "값"이 무엇이냐가 다르다.

### 기본형 대입: 서로 완전히 독립적
```java
int x = 5;
int y = x;   // x의 값 5가 복사되어 y에 저장됨

y = 9;
System.out.println("x = " + x);  // x = 5 (영향 없음)
System.out.println("y = " + y);  // y = 9
```

### 참조형 대입: 같은 객체를 공유하게 됨
숫자 하나를 담는 간단한 상자(Box) 클래스를 예로 들어보자.
```java
class Box {
    int number;
}
```
```java
Box box1 = new Box();
box1.number = 5;

Box box2 = box1;   // box1에 담긴 "참조값"이 복사됨 → box1, box2는 같은 Box 객체를 가리킴
box2.number = 9;

System.out.println("box1.number = " + box1.number);  // 9  ← box1도 영향받음!
System.out.println("box2.number = " + box2.number);  // 9
```
`box2 = box1` 시점에 실제 객체가 복사되는 게 아니라, box1이 가지고 있던 "주소(참조값)"만 복사된다. 그 결과 box1, box2는 서로 다른 변수지만 **메모리상 같은 하나의 Box 객체**를 가리키게 된다. 그래서 box2를 통해 값을 바꾸면 box1로 읽어도 바뀐 값이 보인다.

> 비유: 건물 자체가 복사되는 게 아니라 건물의 "주소"만 복사되는 것과 같다. 주소를 아는 사람이 여러 명이어도 건물은 하나뿐이다.

## 3. 메서드 호출에서도 원리는 같다 (Call by Value)
자바는 메서드를 호출할 때도 매개변수에 값을 "복사"해서 전달한다. 참조형이라 해도 예외 없이 **값(참조값)을 복사**해서 넘긴다는 점이 핵심이다.

### 기본형 매개변수: 원본에 영향 없음
```java
static void addOne(int x) {
    x = x + 1;
}

int score = 10;
addOne(score);
System.out.println(score);  // 10, 그대로 유지
```
`score`의 값 10이 복사되어 매개변수 `x`에 전달된다. 메서드 안에서 `x`를 바꿔도 그건 복사본일 뿐이라 호출자의 `score`에는 영향이 없다.

### 참조형 매개변수: 필드 변경이 원본에도 반영됨
```java
static void levelUp(Box box) {
    box.number = box.number + 1;
}

Box myBox = new Box();
myBox.number = 5;
levelUp(myBox);
System.out.println(myBox.number);  // 6, 변경됨!
```
`myBox`가 가진 참조값이 복사되어 매개변수 `box`에 전달된다. `box`와 `myBox`는 이제 같은 객체를 가리키므로, 메서드 안에서 `box.number`를 바꾸면 `myBox.number`를 읽었을 때도 바뀐 값이 보인다.

**주의**: 메서드 안에서 매개변수 자체에 완전히 새로운 객체를 대입하는 것(`box = new Box();`)은 그 지역 변수의 참조값만 바뀔 뿐, 호출자가 가진 원본 변수에는 영향을 주지 않는다. "필드를 바꾸는 것"과 "매개변수에 새 객체를 대입하는 것"은 다르다는 점을 기억하자.

이 성질은 실무에서 자주 활용된다. 예를 들어 객체를 메서드에 넘겨서 그 객체의 필드를 채우거나(`init` 류 메서드), 값을 조회해서 출력하는(`print` 류 메서드) 식으로 역할을 분리하면 중복 코드를 줄일 수 있다.

## 4. null과 NullPointerException
- 참조형 변수는 "아직 가리키는 객체가 없음"을 뜻하는 `null` 값을 가질 수 있다. (`Box box = null;`)
- `null`인 변수에 대해 `.`으로 필드나 메서드에 접근하려 하면 **NullPointerException(NPE)**이 발생한다. "가리키는 대상이 없는데 그 안을 들여다보려고 했다"는 뜻으로 이해하면 쉽다.
```java
Box box = null;
box.number = 5;  // NullPointerException 발생!
```
- 기본형은 `null`이 될 수 없다. 항상 실제 값을 가지며, 초기화하지 않은 멤버 변수는 자동으로 기본값(`int`는 0, `boolean`은 false 등)을 가진다.

## 확인 문제
1. `Box a = new Box(); Box b = a; b.number = 100;` 실행 후 `a.number`는 얼마인가? 그 이유는?
2. 메서드에 참조형 매개변수를 넘겼을 때, 메서드 안에서 매개변수에 완전히 새로운 객체를 대입하면 호출자의 변수도 바뀌는가?
3. NullPointerException은 언제 발생하는가?

1. 100이다. `b = a`로 참조값이 복사되어 a와 b가 같은 객체를 가리키기 때문에, b를 통한 변경이 a에서도 보인다.
2. 아니다. 매개변수는 참조값의 복사본이므로, 매개변수 자체에 새 객체를 대입해도 그건 지역 변수만 바뀌는 것이고 호출자의 원본 변수에는 영향이 없다.
3. 참조형 변수의 값이 `null`인 상태에서 `.`을 통해 필드나 메서드에 접근하려 할 때 발생한다.

## 핵심 정리
| 구분 | 기본형 | 참조형 |
|---|---|---|
| 저장 내용 | 실제 값 | 객체의 참조값(주소) |
| 연산 | 직접 가능 | 불가능 (필드 접근 후 가능) |
| 대입 | 값 복사 → 독립적 | 참조값 복사 → 같은 객체 공유 |
| 메서드 전달 시 | 원본 변경 안 됨 | 필드 변경은 원본에도 반영 |
| null 가능 여부 | 불가능 | 가능 (접근 시 NPE 주의) |
