# 4강. 생성자

## 학습 목표
생성자가 왜 필요한지, `this` 키워드의 역할, 생성자 오버로딩과 `this()`를 활용한 중복 제거 방법을 이해한다.

## 1. 생성자가 필요한 이유
객체를 만들고 나서 곧바로 초기값을 채워야 하는 경우가 많다. 초기화용 메서드를 직접 만들어 쓸 수도 있다.

```java
public class Coupon {
    String code;
    int discountRate;
}
```
```java
Coupon c1 = new Coupon();
initCoupon(c1, "WELCOME10", 10);

Coupon c2 = new Coupon();
initCoupon(c2, "SUMMER20", 20);

static void initCoupon(Coupon coupon, String code, int discountRate) {
    coupon.code = code;
    coupon.discountRate = discountRate;
}
```
동작은 하지만 두 가지 불편함이 있다.
1. 객체를 생성(`new`)하는 코드와, 초기화(`initCoupon`)하는 코드가 항상 짝을 이뤄 따라다녀야 한다. 둘 중 하나라도 빠뜨리면 값이 비어있는 "빈 깡통" 객체가 만들어질 수 있다.
2. 초기화 로직이 `Coupon` 자신의 데이터를 다루는데도, `Coupon` 밖(별도 메서드)에 놓여 있다. 3강에서 배운 캡슐화 관점에서 보면, 이 초기화 기능도 `Coupon` 안으로 들어가는 게 더 자연스럽다.

이 문제를 자바가 제공하는 **생성자(Constructor)**로 해결할 수 있다. 생성자를 사용하면 객체를 생성하는 시점에 곧바로 필요한 초기화를 강제로 수행할 수 있다.

## 2. this 키워드
생성자를 만들기 전에 `this`부터 이해하고 가자.
```java
public class Coupon {
    String code;
    int discountRate;

    void initCoupon(String code, int discountRate) {
        this.code = code;
        this.discountRate = discountRate;
    }
}
```
`initCoupon`의 매개변수 이름(`code`, `discountRate`)이 멤버 변수 이름과 완전히 같다. 이럴 때 그냥 `code = code`라고 쓰면, 자바는 항상 **더 안쪽 범위(코드 블록상 더 가까운 곳)에 있는 것을 우선시**하기 때문에 매개변수를 매개변수에 대입하는 꼴이 되어 멤버 변수는 전혀 바뀌지 않는다.

멤버 변수를 명확히 가리키려면 앞에 `this.`를 붙인다. `this`는 **이 메서드를 호출한 객체 자신의 참조값**을 의미한다. 그래서 `this.code`는 "지금 이 메서드가 실행되고 있는 바로 그 객체의 code 필드"를 뜻한다.

**this는 생략 가능하다.** 자바는 변수를 찾을 때 먼저 지역 변수(매개변수 포함)를 찾고, 없으면 멤버 변수를 찾는다. 그래서 이름이 겹치지 않는다면 `this` 없이도 멤버 변수에 접근된다. 다만 이름이 겹치는 상황에서는 `this`가 필수다. (참고로 항상 `this`를 붙이는 코딩 스타일도 있는데, 요즘은 IDE가 멤버 변수와 지역 변수를 색상으로 구분해주기 때문에 꼭 필요한 경우에만 쓰는 편이 더 깔끔하다.)

## 3. 생성자 도입
생성자는 문법상 일반 메서드와 비슷하지만 다음 세 가지가 다르다.
- 생성자의 이름은 **클래스 이름과 완전히 같아야** 한다. (대문자로 시작)
- **반환 타입이 없다.** `void`조차 쓰지 않고 아예 비워둔다.
- 나머지 문법은 메서드와 동일하다.

```java
public class Coupon {
    String code;
    int discountRate;

    Coupon(String code, int discountRate) {
        System.out.println("생성자 호출 code=" + code + ", discountRate=" + discountRate);
        this.code = code;
        this.discountRate = discountRate;
    }
}
```
```java
Coupon c1 = new Coupon("WELCOME10", 10);
Coupon c2 = new Coupon("SUMMER20", 20);
```
`new 클래스명(생성자에 맞는 인수 목록)` 형태로 호출하면, 객체를 생성함과 동시에 그 생성자가 자동으로 실행된다. `new` 뒤에 항상 `()`가 붙는 이유가 바로 이것이다 — 객체 생성과 동시에 생성자를 호출한다는 의미가 그 괄호에 담겨 있다.

### 생성자의 진짜 장점: 필수값 입력 강제
직접 정의한 생성자가 있는 클래스는, **그 생성자를 반드시 호출해야만** 객체를 만들 수 있다.
```java
Coupon c3 = new Coupon();  // 컴파일 오류! 매개변수 없는 생성자가 없음
```
```
no suitable constructor found for Coupon(no arguments)
```
이 덕분에 "코드도 없고 할인율도 없는 빈 쿠폰"이 시스템에 등장할 가능성을 원천 차단할 수 있다. 좋은 프로그램은 무한한 자유도를 주는 것이 아니라, 적절한 제약을 걸어 실수를 막는 프로그램이다.

## 4. 기본 생성자
지금까지는 생성자를 만든 적이 없는데도 `new Coupon()`처럼 괄호를 붙여 호출해왔다. 그게 가능했던 이유는, **클래스에 생성자가 단 하나도 없으면 자바 컴파일러가 매개변수 없고 하는 일도 없는 생성자를 자동으로 만들어주기 때문**이다. 이를 **기본 생성자(Default Constructor)**라 한다.

```java
public class Ticket {
    String seatNumber;
}
// 자바가 눈에 보이지 않게 아래와 같은 생성자를 자동 생성해줌
// public Ticket() {}
```

**핵심 규칙: 생성자를 하나라도 직접 정의하면, 자바는 기본 생성자를 더 이상 만들어주지 않는다.** 그래서 위 `Coupon` 예제처럼 매개변수 있는 생성자만 정의해두면, 매개변수 없는 `new Coupon()`은 컴파일 오류가 난다. 매개변수 없는 생성자도 쓰고 싶다면 직접 추가해야 한다.

왜 자바는 이런 편의 기능을 제공할까? 생성자 기능이 굳이 필요 없는 단순한 클래스까지 매번 빈 생성자를 손으로 적어야 한다면 번거롭기 때문이다.

## 5. 생성자 오버로딩과 this()
메서드를 여러 개 정의(오버로딩)할 수 있듯, 생성자도 매개변수 구성을 다르게 해서 여러 개 만들 수 있다.
```java
public class Coupon {
    String code;
    int discountRate;
    int expireDays;

    Coupon(String code, int discountRate) {
        this.code = code;
        this.discountRate = discountRate;
        this.expireDays = 30;  // 기본 유효기간 30일
    }

    Coupon(String code, int discountRate, int expireDays) {
        this.code = code;
        this.discountRate = discountRate;
        this.expireDays = expireDays;
    }
}
```
유효기간을 굳이 지정할 필요 없는 쿠폰은 2개짜리 생성자를, 직접 지정하고 싶으면 3개짜리 생성자를 호출하면 된다.

### this()로 중복 제거
두 생성자를 보면 `this.code = code; this.discountRate = discountRate;` 부분이 중복된다. 생성자 안에서 `this(...)`를 호출하면 같은 클래스의 **다른 생성자**를 호출할 수 있다. (여기서 `this`는 인스턴스 자신을 가리키므로, "자기 자신의 생성자를 호출한다"고 이해하면 된다.)
```java
public class Coupon {
    String code;
    int discountRate;
    int expireDays;

    Coupon(String code, int discountRate) {
        this(code, discountRate, 30);  // 3개짜리 생성자 호출
    }

    Coupon(String code, int discountRate, int expireDays) {
        System.out.println("생성자 호출 code=" + code + ", discountRate=" + discountRate + ", expireDays=" + expireDays);
        this.code = code;
        this.discountRate = discountRate;
        this.expireDays = expireDays;
    }
}
```
**`this()` 규칙: 생성자 코드의 첫 줄에서만 호출할 수 있다.** 아래처럼 다른 코드 뒤에 오면 컴파일 오류다.
```java
Coupon(String code, int discountRate) {
    System.out.println("go");
    this(code, discountRate, 30);  // 오류! 첫 줄이 아님
}
```

3. `this()`는 생성자 코드의 어느 위치에서만 사용할 수 있는가?

## 핵심 정리
| 개념 | 설명 |
|---|---|
| 생성자 | 객체 생성 시점에 자동 호출되는, 이름이 클래스명과 같고 반환 타입이 없는 특별한 메서드 |
| this | 현재 인스턴스 자신을 가리키는 참조값 |
| 기본 생성자 | 생성자가 하나도 없을 때 자바가 자동으로 만들어주는 매개변수 없는 생성자 |
| 생성자 오버로딩 | 매개변수 구성이 다른 생성자를 여러 개 정의 |
| this() | 같은 클래스의 다른 생성자를 호출 (반드시 첫 줄) |
