# 단방향 vs 양방향 데이터 바인딩: React와 Vue는 왜 다르게 설계됐나

*React의 `value` + `onChange`와 Vue의 `v-model`은 결국 같은 문제를 다르게 푼 결과입니다. 이 차이는 문법 취향이 아니라, 두 프레임워크가 데이터 흐름을 바라보는 철학의 차이에서 나옵니다.*

## 1. 데이터 바인딩이란 무엇인가

**데이터 바인딩**(Data Binding)은 상태(모델)와 화면(뷰)을 연결하는 방식을 말합니다. 이 연결이 몇 방향으로 일어나느냐에 따라 단방향과 양방향으로 나뉩니다.

## 2. 단방향 바인딩(One-way Binding)

데이터가 항상 한 방향(모델 → 뷰)으로만 흐릅니다. 화면에서 발생한 입력은 개발자가 작성한 이벤트 핸들러를 거쳐야만 다시 상태에 반영됩니다.

React의 흐름은 두 단계로 명시적으로 나뉩니다.

1. **렌더링**: `State(value)` → `View(<input value=... />)` — state가 화면에 표시됨
2. **이벤트**: `View(사용자 입력)` → `onChange(개발자가 직접 작성)` → `State(setValue())` — 화면 입력이 상태 갱신으로 이어짐 (명시적 코드로 존재)

```jsx
// React: 단방향 바인딩
function Input() {
  const [value, setValue] = useState('');
  return (
    <input
      value={value}
      onChange={(e) => setValue(e.target.value)} // 상태를 명시적으로 갱신
    />
  );
}
```

`input`의 값은 항상 `value` 상태를 그대로 보여줄 뿐이고, 사용자가 타이핑했을 때 실제로 상태를 바꾸는 것은 개발자가 작성한 `onChange` 핸들러입니다. 이 흐름이 명시적으로 코드에 드러난다는 점이 핵심입니다.

## 3. 양방향 바인딩(Two-way Binding)

모델과 뷰가 서로 자동으로 동기화됩니다. 사용자가 입력하면 프레임워크가 알아서 상태를 갱신하고, 반대로 상태가 바뀌면 화면도 자동으로 갱신됩니다.

Vue는 `State(value) ⇄ View(<input v-model />)` — `v-model` 한 줄이 값 표시와 이벤트 갱신을 동시에 처리합니다.

```html
<!-- Vue: 양방향 바인딩 -->
<template>
  <input v-model="value" />
</template>
```

`v-model` 한 줄이 내부적으로는 `:value="value"`와 `@input="value = $event.target.value"`를 합쳐놓은 문법 설탕(syntactic sugar)입니다. 즉 Vue도 결국 이벤트를 받아 상태를 갱신하는 단방향 흐름을 쓰지만, 그 연결 코드를 프레임워크가 대신 작성해주는 것입니다. Angular의 `[(ngModel)]`도 같은 개념입니다.

`v-model`은 엘리먼트 종류에 따라 자동으로 다르게 매핑됩니다.

| 엘리먼트 | 매핑 |
| --- | --- |
| `<input>` / `<textarea>` | value 속성 + input 이벤트 |
| checkbox / radio | checked 속성 + change 이벤트 |
| `<select>` | value 속성 + change 이벤트 |

> **공식 문서 · Vue** — `v-model`은 폼 엘리먼트에 적힌 초기 `value`, `checked`, `selected` 속성을 무시하고, 항상 JavaScript 쪽 상태를 "진실의 원천(source of truth)"으로 취급합니다. 즉 겉보기엔 양방향처럼 보여도 최초 상태의 기준은 여전히 모델 쪽에 있습니다. 동작 조정용 수정자도 있습니다 — `.lazy`(change 시점에만 동기화), `.number`(숫자로 자동 형변환), `.trim`(앞뒤 공백 제거). 참고로 한국어·일본어·중국어처럼 IME를 쓰는 언어는 조합 중에는 `v-model`이 갱신되지 않습니다.

## 4. 왜 이런 차이가 생겼나: 두 프레임워크의 철학

React는 "명시적인 단방향 데이터 흐름"을 설계 원칙으로 삼았습니다. 상태가 어떻게, 어디서 바뀌는지 코드에 항상 드러나야 한다는 철학입니다. 대신 폼처럼 반복적인 상황에서는 코드가 다소 장황해질 수 있습니다.

Vue는 반응형 시스템을 프레임워크 핵심에 두고, `v-model`로 양방향 바인딩을 1급 문법으로 지원합니다. 폼이 많은 화면에서 코드량을 크게 줄여주지만, 규모가 커지면 "어디서 이 값이 바뀐 건지" 추적이 상대적으로 어려워질 수 있습니다.

| 구분 | React | Vue |
| --- | --- | --- |
| 기본 철학 | 단방향 데이터 흐름 명시 | 양방향 바인딩(v-model) 지원 |
| 폼 처리 | value + onChange 직접 작성 | v-model 한 줄로 처리 |
| 상태 변경 추적 | 코드에 명시적으로 드러남 | 프레임워크가 대신 처리 |
| 코드량(폼 많을 때) | 상대적으로 많음 | 상대적으로 적음 |
| 디버깅(대규모) | 상대적으로 쉬움 | 규모 커지면 어려워질 수 있음 |

## 5. 실무에서의 선택

단순한 폼이 많은 관리자 페이지, 빠른 프로토타이핑에는 `v-model`의 간결함이 유리할 수 있고, 상태 변화 원인을 명확히 추적해야 하는 복잡한 협업 프로젝트에서는 React의 명시적인 흐름이 유리할 수 있습니다. Vue에서도 복잡한 폼에서는 `v-model` 대신 명시적 이벤트 핸들링을 선택하기도 하고, React에서도 `react-hook-form` 같은 라이브러리로 반복 코드를 줄이는 절충안을 씁니다.

## 마무리

단방향과 양방향 바인딩은 "어느 것이 더 발전된 기술이냐"의 문제가 아니라, "데이터 흐름의 명시성과 코드 간결함 사이에서 어디에 무게를 둘 것이냐"라는 설계 선택의 문제입니다.
