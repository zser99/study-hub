# [리눅스 개념 5편] 배포판마다 왜 설치 명령어가 다를까? 패키지 관리

윈도우에서는 인터넷에서 설치 파일(.exe)을 받아 더블클릭하면 프로그램이 설치됩니다. 리눅스에서도 소프트웨어를 설치하지만 방식이 조금 다릅니다. 대부분 패키지 매니저라는 도구를 통해 필요한 프로그램을 검색하고, 설치하고, 최신 버전으로 업데이트하고, 필요 없어지면 삭제합니다.

## 배포판마다 다른 도구

리눅스는 하나가 아니라 여러 배포판으로 나뉘어 있고, 각 계열마다 사용하는 패키지 매니저가 다릅니다.

- Debian, Ubuntu 계열: `apt`
- Red Hat, CentOS, Fedora 계열: `yum` 또는 좀 더 최신 버전인 `dnf`
- Arch Linux: `pacman`

예를 들어 Ubuntu에서 nginx라는 웹서버를 설치하고 싶다면 `sudo apt install nginx`라고 치면 되고, CentOS에서는 `sudo yum install nginx`라고 치는 식입니다. 하는 일은 똑같지만 명령어 이름이 배포판마다 다르다는 점만 기억해두면 됩니다.

| 계열 | 매니저 | 설치 | 업데이트 | 삭제 |
|---|---|---|---|---|
| Debian/Ubuntu | apt | `apt install` | `apt update && apt upgrade` | `apt remove` |
| RHEL/CentOS/Fedora | dnf/yum | `dnf install` | `dnf upgrade` | `dnf remove` |
| Arch Linux | pacman | `pacman -S` | `pacman -Syu` | `pacman -R` |

## 저장소(Repository)라는 개념

패키지 매니저가 소프트웨어를 어디서 가져오는지 궁금할 수 있는데, 답은 저장소(repository)입니다. 각 배포판은 신뢰할 수 있는 서버 목록을 미리 등록해두고, 패키지를 설치할 때 그 목록에서 다운로드해옵니다. Ubuntu 기준으로 이 목록은 `/etc/apt/sources.list`에 정의되어 있습니다.

여기서 `apt update`와 `apt upgrade`의 차이를 헷갈리는 경우가 많습니다. `apt update`는 실제로 뭔가를 설치하는 게 아니라, 저장소에 어떤 패키지들이 새로 올라왔는지 목록만 새로고침하는 명령입니다. 그 후에 `apt upgrade`를 실행해야 실제로 설치된 패키지들을 최신 버전으로 업데이트합니다. 즉 `update`로 정보를 갱신하고, `upgrade`로 실제 설치를 진행하는 두 단계로 나뉜다는 걸 기억해두면 좋습니다.

## 의존성 관리, 그리고 의존성 지옥

단순히 설치 파일을 다운로드하는 것 이상의 일을 패키지 매니저가 처리해줍니다. 특정 프로그램을 설치하려면 다른 라이브러리가 먼저 깔려 있어야 하는 경우가 많은데, 이런 의존성 관계를 자동으로 파악해서 필요한 것들을 함께 설치해줍니다. 예전에 패키지 매니저 없이 소스 코드를 직접 컴파일해서 설치하던 시절에는, 프로그램 A를 설치하려면 라이브러리 B가 필요하고, B를 설치하려면 또 C가 필요한 식으로 연쇄적인 의존성 문제, 이른바 "의존성 지옥(dependency hell)"에 자주 시달렸습니다. 패키지 매니저가 등장하면서 이런 문제 대부분이 자동으로 해결됩니다.

## 조금 더 깊이: 다양한 설치 방식

패키지 매니저 외에도 소프트웨어를 설치하는 방법은 여러 가지가 있습니다.

- **소스 컴파일**: 저장소에 없는 최신 버전이나 특수한 옵션이 필요할 때는 소스 코드를 직접 받아서 `./configure`, `make`, `make install` 순서로 컴파일해 설치하기도 합니다. 유연하지만 의존성을 직접 챙겨야 하는 번거로움이 있습니다.
- **Snap, Flatpak**: 필요한 라이브러리를 패키지 안에 통째로 묶어서 배포판 환경에 관계없이 동일하게 동작하도록 만든 최신 방식입니다. 설치가 간편한 대신 파일 용량이 크고 실행 속도가 조금 느릴 수 있습니다.

## 왜 알아야 할까

리눅스로 뭔가를 하려고 하면 결국 필요한 도구를 설치하는 것부터 시작하게 됩니다. 새로운 서버에 접속했을 때 가장 먼저 하는 일 중 하나가 바로 필요한 패키지들을 설치하는 것이고, 그래서 이 명령어들에 익숙해지는 게 실전에서 가장 먼저 몸에 배어야 할 습관 중 하나입니다. 특히 `update`와 `upgrade`의 차이, 그리고 의존성이 왜 자동으로 해결되는지 원리를 알아두면 나중에 패키지 설치가 꼬였을 때 훨씬 침착하게 원인을 찾을 수 있습니다.
