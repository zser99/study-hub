# [리눅스 개념 4편] 셸(Shell), 사용자와 커널 사이의 통역사

터미널 창에 명령어를 치면 컴퓨터가 알아듣고 실행합니다. 이게 당연해 보이지만, 사실 이 과정을 중간에서 담당하는 프로그램이 따로 있습니다. 바로 셸(Shell)입니다. 셸은 사용자가 입력한 명령을 해석해서 커널에 전달하는 일종의 통역사 역할을 합니다.

## 어떤 셸을 쓰게 될까

가장 널리 쓰이는 셸은 bash입니다. 대부분의 리눅스 배포판에서 기본값으로 설정되어 있고, 최근에는 자동완성이나 테마 기능이 강화된 zsh를 쓰는 사람도 많이 늘었습니다. 지금 내가 어떤 셸을 쓰고 있는지는 `echo $SHELL`로 확인할 수 있고, 어떤 셸을 쓰든 기본 개념은 크게 다르지 않습니다.

## 명령어 조합의 힘

셸을 제대로 활용하려면 아래 세 가지 개념을 이해하는 게 중요합니다.

- 파이프(`|`): 한 명령의 출력 결과를 다른 명령의 입력으로 바로 연결합니다. 예를 들어 `ps aux | grep nginx`라고 치면, 전체 프로세스 목록에서 nginx라는 이름이 포함된 줄만 걸러서 볼 수 있습니다.
- 리다이렉션(`>`, `>>`): 명령의 출력 결과를 화면 대신 파일로 저장합니다. `>`는 덮어쓰기, `>>`는 이어쓰기입니다. 참고로 `2>`는 정상 출력이 아닌 에러 메시지만 따로 파일로 보내고 싶을 때 씁니다.
- 와일드카드(`*`, `?`): 여러 파일을 한 번에 지정할 때 씁니다. `*.txt`라고 하면 확장자가 txt인 파일 전부를 가리키고, `?`는 정확히 한 글자를 대신합니다.

![파이프와 리다이렉션으로 이어지는 명령어 흐름](images/04_pipeline.png)

| 기호 | 이름 | 역할 |
|---|---|---|
| `\|` | 파이프 | 앞 명령의 출력을 뒤 명령의 입력으로 연결 |
| `>` | 리다이렉션(덮어쓰기) | 출력을 파일로 저장 |
| `>>` | 리다이렉션(이어쓰기) | 출력을 파일 끝에 추가 |
| `2>` | 에러 리다이렉션 | 에러 메시지만 파일로 저장 |
| `*`, `?` | 와일드카드 | 여러 파일을 패턴으로 지정 |

## 조금 더 깊이: 변수, 명령어 치환, 서브셸

셸 안에서도 변수를 만들어 쓸 수 있습니다. `name="hello"`처럼 선언하고 `$name`으로 값을 꺼내 쓰는데, 이렇게 만든 변수는 기본적으로 현재 셸 안에서만 유효합니다. 이 변수를 자식 프로세스에서도 쓸 수 있게 하려면 `export`로 환경 변수로 승격시켜야 합니다.

또 하나 알아두면 유용한 게 명령어 치환입니다. `$(명령어)` 형태로 감싸면 그 명령어의 실행 결과를 다른 명령어 안에 바로 끼워넣을 수 있습니다. 예를 들어 `echo "오늘은 $(date +%Y-%m-%d)입니다"`라고 치면 date 명령의 결과가 문장 안에 그대로 삽입됩니다.

괄호로 명령을 묶으면 `( )` 서브셸이라는 별도의 자식 셸에서 명령이 실행되어, 그 안에서 바뀐 디렉토리나 변수가 바깥 셸에 영향을 주지 않습니다. 반면 중괄호 `{ }`로 묶으면 서브셸을 만들지 않고 현재 셸에서 그대로 실행됩니다. 미묘한 차이지만 스크립트를 작성하다 보면 종종 마주치는 부분입니다.

## 반복 작업을 줄여주는 습관들

자주 쓰는 긴 명령어는 `alias`로 짧은 별칭을 만들어두면 편합니다. 예를 들어 `alias ll='ls -alF'`라고 등록해두면 `ll`만 쳐도 상세 목록이 나옵니다. 이런 alias나 자주 쓰는 환경 변수 설정은 매번 새로 입력하지 않도록 `~/.bashrc` 같은 셸 설정 파일에 넣어두면, 터미널을 새로 열 때마다 자동으로 적용됩니다. 또한 방금 친 명령어들이 기억나지 않을 때는 `history` 명령이나 위 방향키로 과거 명령어를 다시 불러올 수 있고, `Ctrl+R`로 과거 명령어를 검색할 수도 있습니다.

## 왜 이게 중요할까

이런 기능들을 자유자재로 조합해서 쓸 줄 알게 되면 반복 작업의 속도가 확 달라집니다. 파일 100개 중에서 특정 조건에 맞는 것만 찾고, 그 결과를 정리해서 파일로 저장하는 작업을 명령어 한 줄로 처리할 수 있게 되는 거죠. GUI로는 몇 분씩 걸릴 작업이 셸 명령 조합 몇 개로 몇 초 만에 끝나는 경험을 하다 보면, 왜 개발자들이 여전히 터미널을 떠나지 못하는지 이해가 갈 겁니다.
