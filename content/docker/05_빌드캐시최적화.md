# [Docker 개념 5편] 왜 두 번째 빌드는 20초에서 1초로 줄어들까

`docker build` 명령을 실행하면 Docker는 Dockerfile의 각 명령을 순서대로 실행하면서 명령마다 레이어를 하나씩 만듭니다. 그런데 매번 처음부터 전부 다시 만들 필요는 없습니다. 이전 빌드에서 사용했던 것과 동일한 명령이라면, Docker는 다시 실행하는 대신 캐시된 결과를 그대로 재사용합니다. 이게 바로 빌드 캐시입니다.

## 캐시가 무효화되는 세 가지 경우

빌드 캐시를 효과적으로 쓰려면, 어떤 경우에 캐시가 깨지는지부터 알아야 합니다. 공식 문서는 다음 세 가지를 꼽습니다.

1. **`RUN` 명령의 내용이 바뀌면** 그 레이어의 캐시가 무효화됩니다.
2. **`COPY`나 `ADD`로 복사되는 파일이 바뀌면** (내용뿐 아니라 권한 같은 속성 변경도 포함) 캐시가 무효화됩니다.
3. **한 레이어가 무효화되면, 그 뒤에 오는 모든 레이어도 함께 무효화됩니다.** 베이스 이미지든 중간 레이어든, 앞선 레이어가 바뀌면 그 이후에 의존하는 레이어들도 도미노처럼 다시 빌드됩니다.

## 실제로 얼마나 차이가 날까

다음 Dockerfile로 실습해보겠습니다.

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY . .
RUN yarn install --production
EXPOSE 3000
CMD ["node", "./src/index.js"]
```

처음 빌드하면 의존성 설치까지 포함해서 20초가 걸립니다. 아무것도 바꾸지 않고 다시 빌드하면 1초 만에 끝나는데, 모든 레이어가 캐시에서 그대로 재사용되기 때문입니다.

문제는 소스 코드 한 줄만 바꿔도 이 구조에서는 `COPY . .`가 무효화되고, 그 뒤에 있는 `RUN yarn install`까지 통째로 다시 실행된다는 점입니다. 의존성은 그대로인데 매번 재설치하는 건 명백한 낭비죠.

## 해결책: 자주 바뀌지 않는 것을 먼저 복사한다

의존성 목록(`package.json`)과 소스 코드를 분리해서 복사하면 이 문제를 해결할 수 있습니다.

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install --production
COPY . .
EXPOSE 3000
CMD ["node", "src/index.js"]
```

이렇게 바꾸면 `package.json`이 바뀌지 않는 한 `RUN yarn install --production` 레이어는 계속 캐시에서 재사용됩니다. 소스 코드만 바뀌었을 때는 마지막 `COPY . .`부터만 다시 실행되므로, 빌드 시간이 눈에 띄게 줄어듭니다. 실제로 공식 문서의 실습에서는 이 구조 변경만으로 재빌드 시간이 16초에서 1.2초로 줄었습니다.

## `.dockerignore`도 함께 챙기기

`COPY . .`처럼 디렉토리 전체를 복사할 때, `node_modules`처럼 불필요하거나 매번 바뀌는 파일까지 함께 복사되면 캐시 무효화가 더 자주 일어납니다. Dockerfile과 같은 위치에 `.dockerignore` 파일을 만들어 제외할 항목을 지정해두면, 빌드 컨텍스트 전송 자체가 가벼워지고 불필요한 캐시 미스도 줄어듭니다.

```plaintext
node_modules
```

## 조금 더 깊이: 캐시는 로컬에만 머물지 않는다

빌드 캐시는 로컬 디스크뿐 아니라 원격 저장소(레지스트리)에도 보관할 수 있습니다. CI 환경처럼 매번 새로운 머신에서 빌드가 실행되는 상황이라면, 이전 빌드의 캐시를 레지스트리에서 가져와 재사용하는 방식으로 CI 빌드 시간도 크게 줄일 수 있습니다. 이런 캐시 백엔드 설정은 BuildKit(Docker의 최신 빌드 엔진)의 `--cache-from`, `--cache-to` 옵션으로 구성합니다.

## 참고표

| 상황 | 캐시 유지 여부 |
|---|---|
| Dockerfile과 소스 모두 그대로 재빌드 | 전부 캐시 재사용 |
| `RUN` 명령 내용 변경 | 해당 레이어부터 무효화 |
| `COPY` 대상 파일 내용/권한 변경 | 해당 레이어부터 무효화 |
| 앞선 레이어가 무효화됨 | 뒤따르는 모든 레이어도 무효화 |
